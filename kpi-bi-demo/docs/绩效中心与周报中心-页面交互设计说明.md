# 绩效中心与周报中心——页面与交互设计说明

> 当前版本：2026-07-13  
> 实现形态：React + 静态 HTML 前端 Demo，使用稳定 Mock、React 内存状态和浏览器 `localStorage` 演示流程；不代表已接入后端、数据库、组织权限服务或消息服务。

## 1. 产品定位

绩效中心定位为“月度绩效目标管理”，覆盖目标下发、员工确认、结果填报、逐级评分、HR 复审、CEO 审批、面谈归档和申诉裁决。周报中心用于员工填写、团队查看和领导汇总。周报是可追溯参考，不自动修改绩效评分。

用户界面统一使用“绩效目标”和“CEO”语义；旧术语仅可能作为历史技术字段或内部样式类名保留，不在页面展示。

## 2. 角色与权限

| 角色 | 数据范围 | 可执行动作 | 明确禁止 |
| --- | --- | --- | --- |
| 员工 | 仅本人 | 确认目标、提出异议、拒绝待确认变更、填报结果、提交周报、发起申诉 | 查看或处理他人记录 |
| Leader | 本人及责任范围 | 下发/变更目标、审核结果、一级或二级评分、录入加减分、提供申诉依据、面谈归档、重新开放周报 | 处理责任范围外记录、代替 HR 或 CEO |
| HR | 全公司 | 维护岗位绩效目标模板、HR 复审、申诉调查、异常管理、重新开放周报 | 代替 Leader 评分、代替 CEO 审批或裁决 |
| CEO | 全公司 | 最终绩效审批、申诉最终裁决 | 代替 Leader 或 HR 节点 |

Demo 同时在按钮可见性和动作执行函数中校验角色及责任范围。身份切换只模拟权限上下文，不等同于生产鉴权。

## 3. 绩效目标模型

每月目标由三部分组成：

1. 岗位通用绩效目标：HR 按“部门 + 岗位”创建的模板必选项，Leader 下发时不能删除；
2. 个人月度重点目标：Leader 可新增、编辑、删除；
3. 独立加减分项：不参与目标权重合计。

岗位通用目标与个人月度目标共同参与权重校验，合计必须为 100%；否则禁止下发并展示当前合计和原因。加减分项独立计分。

HR 在绩效中心按部门和适用岗位创建、维护绩效模板。Leader 进入现有月度目标下发页后，系统按所选员工的部门和岗位带出对应模板；Leader 可在本次下发草案中调整必选目标的要求与权重、增删个人月度目标，但不会回写或覆盖 HR 原模板。一次选择多个岗位时，每位员工保留其对应岗位模板；当前编辑仅影响选中的部门岗位草案。

## 4. 目标状态、异议与版本

### 4.1 首次下发

```text
绩效目标待下发
  → 待员工确认绩效目标
  → 绩效目标已生效
  → 待员工填报结果
```

员工可以确认或提出异议。异议原因必填：

```text
待员工确认绩效目标
  → 目标异议处理中
  → Leader调整并重新下发
  → 待员工确认绩效目标
```

### 4.2 生效后变更

Leader 必须填写变更原因，系统生成待确认新版本。员工确认后新版本生效，旧版本归档；员工拒绝时原版本继续生效。变更、确认和拒绝都使用期望版本号，旧页面重复提交会返回版本冲突，不覆盖新数据。

详情页展示当前目标版本、历史版本、状态、变更原因、操作人和时间。

## 5. 结果填报、审核和评分

员工逐项目标填写：实际完成结果、完成情况说明、证明材料以及引用的项目、任务或周报信息。Leader 只能审核，不能静默修改员工原文；证明不足时必须填写原因并退回员工补充，原始填报和退回快照继续保留。

评分公式：

```text
需要二级复评：单项目标评分 = 一级评分 × 60% + 二级评分 × 40%
无需二级复评：单项目标评分 = 一级评分
基础绩效分 = Σ（单项目标评分 × 目标权重）
最终绩效分 = clamp（基础绩效分 + 加减分，0，100）
```

- 加减分由直属 Leader 直接录入并生效；
- 所有加减分累计限制在 -10 至 +10；
- 每条加减分必须填写原因和证明材料；
- 计算保留两位小数，以未取整分数判断等级；
- 等级：S 为 80–100，A 为 70–不足80，B 为 60–不足70，C 为 55–不足60，D 为不足55。

## 6. 复审、审批、面谈与归档

主流程：

```text
待员工填报结果
  → 待一级领导评分
  → [可选] 待二级领导复评
  → 待HR复审
  → 待CEO审批
  → 待反馈与面谈
  → Leader提交面谈记录和改进计划
  → 已结束
```

退回规则：

- 证明材料不足：Leader 退回员工补充；
- 评分、评语或加减分有问题：退回 Leader 重新评分；
- HR 意见问题：HR 修改后重新提交；
- CEO 不批准：退回 Leader，之后重新经过 HR 复审和 CEO 审批。

所有退回原因必填，日志保留前后状态、评分/评语快照、操作人和时间。CEO 通过后由 Leader 提交面谈记录并直接归档，不再要求员工确认。

## 7. 申诉流程与结果版本

```text
申诉已提交
  → HR调查中
  → 待CEO裁决
  → 驳回 / 部分成立 / 成立
```

- 员工提交原因和证据；
- HR 记录调查结论；
- Leader 可提供原评分依据；
- CEO 填写裁决理由；部分成立或成立时必须填写修正分数；
- 驳回保留原结果；部分成立或成立生成绩效结果 V2，V1 归档但不删除；
- 详情保留申诉材料、调查记录、裁决理由、调整前后分数和等级、操作人、时间。

## 8. 绩效中心列表与指标卡

列表支持月份、部门、人员、等级和状态筛选，并展示目标确认、结果填报、一级/二级评分、加减分、最终分、等级、流程和申诉状态。

顶部四张指标卡只作展示，不具有按钮语义、点击事件、筛选联动或可点击光标：

- 绩效目标确认率；
- 评分复审完成率；
- 待受理申诉数；
- S 级人数。

统计范围统一为“当前周期 ∩ 当前角色数据范围 ∩ 部门筛选 ∩ 人员搜索”，不受状态页签、状态筛选和等级筛选影响。

## 9. 周报中心

周报页面继续由 `public/weekly-report.html` 承载，并通过固定 `employeeId + 周期` 写入 `localStorage`，绩效中心和数据看板读取同一提交记录作为参考。

### 9.1 状态与版本

支持：草稿、已提交、已锁定、逾期未交、逾期已提交、待修改。

```text
草稿
  → 截止前提交：已提交V1
  → 截止前更新：已提交V2
  → 截止后：已锁定

草稿 → 逾期未交 → 逾期补交 → 逾期已提交
已锁定/逾期已提交 → Leader或HR填写原因重新开放 → 待修改 → 重新提交新版本
```

时间判断使用固定 Demo 时间，测试不依赖运行机器的真实时间。提交记录保留原截止时间、实际提交时间、版本、状态、逾期时长和操作日志。重复请求与旧版本提交会被拒绝。

### 9.2 草稿权限

Leader 可以看到成员处于草稿或填写中，但不能查看草稿正文、AI 摘要、成果、风险和计划；草稿与逾期未交成员都可发送提醒。只有正式提交后才展示完整周报。截止后的正式周报可由 Leader 或 HR 填写原因后重新开放，原版本不覆盖。

### 9.3 跨模块引用

绩效中心的周报参考使用 `src/performance/weeklyReference.js` 聚合；数据看板使用 `src/dashboard/weeklyReportBridge.js` 读取。两者均优先使用周报页面正式提交记录，草稿只表现为未提交，不读取正文。周报数据不参与绩效评分公式。

## 10. 日志与反馈

目标下发、确认、异议、重新下发、版本变更、结果提交/退回、两级评分、加减分、HR 复审、CEO 审批/退回、面谈归档、申诉调查/裁决、周报提交/更新/重新开放/逾期补交均追加操作日志。

关键提交提供提交中、成功、校验失败、无权限、重复提交和版本冲突反馈。失败不会清空表单输入，用户可修改后重试。

## 11. 当前数据来源与 Mock 边界

| 能力 | 当前来源 | Demo 限制 |
| --- | --- | --- |
| 绩效记录 | `src/performance/seed.js` | React 内存，刷新恢复种子 |
| 评分/权限/版本规则 | `src/performance/logic.js` | 纯前端校验，不能替代服务端鉴权与事务 |
| 部门岗位绩效模板 | `App.jsx` 的 `departmentPerformanceTemplatesSeed` | HR 可按部门和岗位新建、维护；当前结果仅当前页面内存 |
| 周报状态规则 | `src/weekly/weeklyLogic.js` 与 HTML 同步实现 | 无真实工作流服务 |
| 周报提交记录 | 浏览器 `localStorage` | 仅当前浏览器，未跨用户同步 |
| 绩效周报引用 | `src/performance/weeklyReference.js` | 未接真实项目/任务/附件服务 |
| 操作日志 | 前端数组 | 无服务端不可篡改审计能力 |

生产实现仍需补充统一身份认证、组织关系、服务端权限、并发事务、附件存储、消息待办、审计日志和真实 API。

## 12. 验收映射

自动测试覆盖：目标权重、60/40 公式、加减分边界、S/A/B/C/D 边界、角色越权、异议、目标 V2、拒绝保留 V1、结果退回、申诉结果 V2、版本冲突、指标卡不可点击及统计口径、草稿隐私、截止前更新、截止后锁定、重新开放和逾期补交。

人工验收需分别切换员工、Leader、HR、CEO，检查列表数据范围、节点按钮状态、下发页结构、目标/结果版本详情，以及周报团队视图中的草稿隐私和重新开放交互。
