# 绩效中心 1:1 对标 HTML 文件重构设计

日期：2026-07-02

## 目标

将当前 React 原型中的“绩效中心”重构为与用户提供的 HTML 文件高度一致的月度绩效管理页，做到：

- 页面信息架构尽量 1:1 对标参考 HTML
- 交互形态从“同页录入工作台”切换为“搜索区 + 统计区 + 流程区 + 列表区 + 业务弹窗”
- 保留并映射真实绩效制度与 Excel 操作逻辑
- 形成完整可交互原型，而不是静态展示稿

## 当前问题

当前版本虽然已经把评分逻辑和真实 Excel 字段映射到了页面中，但主结构仍是：

- 左侧考核对象列表
- 右侧整页录入表单
- 申诉作为补充弹窗

这与用户提供的 HTML 文件差异明显：

- 参考文件以“月度绩效管理列表页”为主入口，而不是录入工作台
- 参考文件更强调组织级筛选、流程推进、状态分发和弹窗处理
- 参考文件中 OKR 下发、结果录入、评分、审批、面谈、申诉都挂在同一业务列表上

因此这次不是样式微调，而是绩效中心页面模型切换。

## 设计原则

- 优先还原参考 HTML 的页面组织方式，而不是保留现有录入页布局
- 逻辑使用我们已经整理出的真实制度和 Excel 字段，不退回到纯演示数据
- 页面仍保持 React 原型可维护性，避免把整份 HTML 直接硬塞进单个巨大组件
- 交互只做到“原型级完整可用”，不追求真实后端、权限系统和持久化

## 页面结构

绩效中心将重构为单页主导结构，按从上到下的顺序组织：

### 1. 页面标题区

- 标题：`绩效中心`
- 副标题：`月度绩效目标下发、结果录入、逐级评分、委员会审批、绩效面谈与申诉处理`
- 右侧按钮组：
  - 月度 OKR 下发
  - 月末推进
  - 导出
  - 制度规则

用途：

- 对齐参考 HTML 的“标题 + 全局业务操作入口”
- 把原来散落在工作区内的动作收束到页头

### 2. 搜索筛选区

字段与参考 HTML 对齐：

- 考核月份
- 部门
- 姓名/岗位关键词
- 等级
- 申诉状态

动作：

- 查询
- 重置

行为：

- 所有概览卡片、流程状态统计、表格记录同步联动
- 筛选结果作为当前视图上下文

### 3. 概览卡片区

默认展示四张卡片：

- 待确认目标
- 待处理评分
- 待委员会审批
- 待处理申诉

每张卡片包含：

- 标题
- 数值
- 说明文案
- 简单视觉标识

用途：

- 让绩效中心从“单人录入页”切换为“组织级绩效运营面板”

### 4. 月度流程时间线

按参考 HTML 展示流程节点：

- 目标下发
- 员工确认
- 执行中
- 结果录入
- 一级评分
- 二级评分
- HR 复核
- 委员会审批
- 反馈面谈
- 绩效申诉
- 申诉受理

行为：

- 节点展示时间说明
- 节点支持按当前记录分布显示完成、进行中、风险状态

### 5. Tab 列表区

列表顶部采用状态 tabs，对齐参考 HTML：

- 全部
- 目标待下发
- 待确认
- 执行中
- 待结果录入
- 待一级评分
- 待二级评分
- 待HR复核
- 待委员会审批
- 待反馈面谈
- 已归档
- 申诉中

表格列按参考 HTML 和真实业务综合设计：

- 员工信息
- 部门 / 岗位
- 绩效链路
- 目标确认
- 结果录入
- 一级评分
- 二级评分
- 综合得分
- 等级
- 奖金应用
- 申诉状态
- 当前流程状态
- 操作列

操作列根据记录状态动态显示按钮，例如：

- 查看详情
- 录入结果
- 一级评分
- 二级评分
- HR复核
- 委员会审批
- 面谈反馈
- 发起申诉
- 处理申诉

### 6. 分页区

原型保留视觉分页与页码切换行为，但数据仍使用本地数组分页，不引入真实服务端分页。

## 弹窗体系

绩效中心的主要业务不再在页面右侧整页完成，而改为弹窗处理。

### 1. 绩效详情弹窗

展示：

- 基础信息
- 绩效指标明细
- 实际完成情况
- 一级/二级评分与评语
- 综合得分、等级、奖金应用
- 申诉状态

用途：

- 作为所有角色的统一查看入口

### 2. 结果录入弹窗

用于员工或可代录角色录入：

- 指标完成情况
- 实证材料
- 备注说明

保存后状态推进：

- `执行中` -> `待结果录入`
- 提交后 -> `待一级评分`

### 3. 一级评分弹窗

用于第一级上级填写：

- 一级评分
- 一级评语

提交后状态推进为：

- `待一级评分` -> `待二级评分`

### 4. 二级评分弹窗

用于第二级上级填写：

- 二级评分
- 二级评语

提交后状态推进为：

- `待二级评分` -> `待HR复核`

### 5. HR复核弹窗

用于综合管理中心/HR：

- 核对评分材料
- 校验完整性
- 填写复核意见

提交后状态推进为：

- `待HR复核` -> `待委员会审批`

### 6. 委员会审批弹窗

用于绩效管理委员会：

- 查看综合结果
- 审批通过 / 退回说明

通过后状态推进为：

- `待委员会审批` -> `待反馈面谈`

### 7. 面谈反馈弹窗

用于部门负责人或上级完成：

- 面谈纪要
- 改进建议
- 是否已完成反馈

提交后状态推进为：

- `待反馈面谈` -> `已归档`

### 8. 发起申诉弹窗

按真实制度与参考 HTML 展示：

- 申诉人
- 部门
- 职位
- 申诉日期
- 申诉内容
- 证据清单

提交后：

- `appealStatus` -> `待受理`
- `status` -> `申诉中`

### 9. 处理申诉弹窗

展示：

- 申诉基础信息
- 调查结果
- 建议方案
- HR意见
- 委员会意见

处理动作：

- 标记调查中
- 驳回申诉
- 裁定完成

裁定完成后：

- `appealStatus` -> `已裁定`
- `status` -> `已归档`
- 如设计为示例纠偏场景，可按规则微调最终得分与等级

### 10. 月度 OKR 下发弹窗

按参考 HTML 还原：

- 考核月份
- 发布范围
- OKR 主题
- 发布说明
- 选择绩效维度
- 编辑指标名称 / 评定标准 / 数据来源
- 选择发布对象

提交后：

- 为目标对象重置周期绩效记录
- 写入所选绩效维度
- 状态切换为 `待确认`

### 11. 制度规则弹窗

展示制度摘要：

- 考核周期
- 考核维度
- 评价权重
- 综合得分公式
- 等级规则
- 申诉机制
- 奖金应用

## 真实制度映射

新页面结构虽然对标参考 HTML，但底层逻辑继续以真实材料为准：

- 月度考核周期
- 员工结果录入提前 5 个工作日
- 评价者评分提前 3 个工作日
- 综合管理中心复核提前 2 个工作日
- 周期结束后 3 个工作日内面谈反馈
- 申诉需在知晓结果后 2 个工作日内提交
- 综合得分 = 指标加权得分 + 加减项
- 一级上级 60%，二级上级 40%

Excel 中的真实表结构也继续保留：

- 质量维度
- 效率维度
- 文化践行维度
- 加减分项

因此新页面只是更换容器和交互形式，不改真实绩效口径。

## 将替换的旧结构

以下当前结构将被降级或移除：

- 绩效页左侧“考核对象列表”主导航结构
- 右侧整页“绩效考核录入页”主布局
- 以同页大表单为核心的工作台模式

保留但重用的能力：

- 行评分计算
- 综合得分计算
- 等级映射
- 申诉保存逻辑
- 基础样例数据与真实字段模板

## 组件拆分

为避免把参考 HTML 的所有内容塞进一个组件，重构时拆分为：

- `PerformanceCenter`
- `PerformanceHeader`
- `PerformanceFilters`
- `PerformanceMetrics`
- `PerformanceTimeline`
- `PerformanceTabs`
- `PerformanceTable`
- `PerformanceDetailModal`
- `PerformanceResultModal`
- `PerformanceScoreModal`
- `PerformanceAppealModal`
- `PerformanceOkrModal`
- `PerformanceRuleModal`

如果本轮实现成本过高，可在文件层面先保留于 `App.jsx`，但组件边界应先以函数形式拆出。

## 状态推进规则

页面内状态机采用以下主链路：

`目标待下发` -> `待确认` -> `执行中` -> `待结果录入` -> `待一级评分` -> `待二级评分` -> `待HR复核` -> `待委员会审批` -> `待反馈面谈` -> `已归档`

申诉为旁路：

- 从 `待反馈面谈` 或 `已归档` 发起申诉
- 进入 `申诉中`
- 调查完成后回到 `已归档`

## 非目标

本轮不做：

- 真实后端接口
- 真正登录权限体系
- 数据库存储
- 文件上传
- 导出真实 Excel
- 严格复刻参考 HTML 的所有原生脚本实现方式

## 验收标准

满足以下条件视为本轮设计达标：

- 绩效中心首页结构与参考 HTML 高度一致
- 不再以“同页录入工作台”为主入口
- 列表、流程、状态、统计和弹窗形成闭环
- 核心业务按钮可实际操作并推进记录状态
- 真实绩效制度和 Excel 指标逻辑仍然成立
- 页面在桌面端与常规窄屏下都能正常使用

## 实施顺序建议

1. 重构绩效中心主页面骨架与数据视图
2. 重建状态 tabs、表格列和操作列
3. 接入详情、结果录入、评分、审批、反馈弹窗
4. 接入申诉处理与制度规则弹窗
5. 接入月度 OKR 下发弹窗
6. 清理旧录入页样式与无效状态
