# 统一工作台任务内容格式与展示规则

> 最新展示决策：任务工作台采用全宽双列任务卡片，显示业务来源、任务标题、两行摘要、任务状态、任务下发时间和进入指示；只有选题、项目显示业务编码。列表与详情概览不展示人员姓名。统一工作台没有逾期规则，状态仅包含待处理、已退回、已完成。

## 1. 目标

统一工作台不应把所有任务内容都压缩成相同的纯文本。不同内容应使用与其信息特征匹配的展示组件，让用户在列表中快速判断“是什么、要做什么、何时下发”，在详情抽屉中理解“具体内容和处理要求”，最终进入来源业务页完成操作。

本规范按内容格式分类，不按绩效、招聘、项目、周报、SSC 等业务模块分类。同一种内容无论来自哪个模块，都使用同一种展示规则。

## 2. 三级展示边界

| 展示层级 | 主要目标 | 内容密度 | 允许展示 | 不承担 |
|---|---|---|---|---|
| 工作台任务列表 | 快速扫描任务 | 中低 | 标题、业务来源、两行摘要、三态状态、任务下发时间；选题和项目编码 | 其他模块编码 ID、人员姓名、完整阅读、录入、审批、时效判断 |
| 任务详情抽屉 | 理解任务上下文和关键内容 | 中 | 结构化字段、关键指标、意见、附件预览、内容摘要 | 复杂编辑、大表格、完整流程操作 |
| 来源业务详情页 | 完成真实业务处理 | 高 | 完整内容、全部附件、编辑表单、审批、日志、版本 | 无 |

核心原则：列表展示“结论和数量”，抽屉展示“关键内容”，来源业务页展示“完整内容并处理”。

## 3. 任务列表的统一骨架

### 3.1 基础结构

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ 对象名称 · 当前动作                        [任务状态]  任务下发时间  > │
│ 业务来源 · 业务编号（仅选题/项目）                                  │
└─────────────────────────────────────────────────────────────────────────┘
```

### 3.2 固定信息

| 信息 | 格式规则 |
|---|---|
| 标题 | `{业务对象} · {当前需要执行的动作}`，最多 1 行，不写大段背景 |
| 业务来源 | 显示绩效、招聘、项目、周报或 SSC；只有选题、项目可追加业务编码 |
| 任务状态 | 只允许待处理、已退回、已完成 |
| 任务下发时间 | 优先显示来源业务提供的完整日期时间；缺失时显示“待记录” |

### 3.3 可变内容摘要区

当前任务列表启用最多两行的行动摘要；完整业务字段、附件和流程信息放入详情抽屉或来源业务页。

## 4. 内容格式与展示方式总表

| 内容格式 | 列表展示 | 详情抽屉展示 | 来源业务页展示 |
|---|---|---|---|
| 短文本 | 直接展示 1 行 | 完整段落 | 完整内容/可编辑 |
| 长文本/富文本 | 2 行摘要 + 省略 | 分段摘要，可展开 | 完整富文本 |
| 键值信息 | 最多 2 个关键值 | 2 列键值网格 | 全部字段 |
| 数值/指标 | 1–3 个紧凑指标 | 指标卡组 + 口径 | 完整指标与明细 |
| 进度 | 百分比或完成数 | 进度条 + 阶段说明 | 全部阶段与更新操作 |
| 清单 | `已完成 n/m` | 可读清单 | 完整清单，可勾选 |
| 流程/步骤 | `当前第 n/m 步` | 精简步骤条 | 完整流程与日志 |
| 日期/时间 | 任务下发时间 | 下发时间及必要的业务节点时间 | 完整日程与调整入口 |
| 人员/组织 | 负责人 1 人 | 负责人、下发人、协作人 | 完整组织与分工 |
| 状态/标签 | 待处理、已退回或已完成 | 状态说明与来源 | 完整状态历史 |
| 审批意见/评论 | 结论 + 1 行摘要 | 引用块 + 人员 + 时间 | 完整意见与回复 |
| 风险/退回原因 | 警告摘要 | 警示块 + 分类 + 说明 | 完整原因与整改 |
| 关联对象/链接 | 对象名，必要时带业务编号 | 对象摘要卡 | 跳转完整详情 |
| 文件附件 | 图标 + `n 个附件` | 文件卡片列表 | 全部附件管理 |
| 图片/凭证 | 图标 + `n 张图片` | 缩略图宫格，可预览 | 全部图片与上传 |
| 表格 | `n 条数据` + 关键结论 | 迷你表格，最多 5 行 | 完整表格、筛选、分页 |
| 分段内容 | 显示完成情况或首段摘要 | 分区卡片 | 完整分段表单 |
| 版本/差异 | `Vn` + 变更项数量 | 前后值对比 | 完整版本历史 |
| 空缺内容 | `待补充：字段名` | 空状态 + 缺失项 | 对应字段编辑入口 |
| 敏感内容 | 脱敏值或不展示 | 按权限脱敏 | 按权限查看完整值 |

## 5. 各内容格式的详细规则

### 5.1 短文本

适用：一句话任务说明、简短备注、单一结论。

- 列表：直接显示，最多 1 行；超过宽度使用省略号。
- 抽屉：以普通正文展示，保留完整语义。
- 不使用标签承载完整句子。

```text
确认本月绩效目标，如有异议需填写原因后提交。
```

### 5.2 长文本与富文本

适用：选题摘要、项目说明、周报正文、申诉陈述。

- 列表：抽取纯文本摘要，最多 2 行；去除图片、表格和富文本样式。
- 抽屉：按自然段展示前 3 段或前 500 字，超过部分提供「展开全文」。
- 业务页：保留标题、段落、列表、引用等完整结构。
- 不允许在列表中显示滚动文本框。

```text
列表：补充项目延期原因及后续处理计划……

抽屉：
项目背景
正文段落……

影响说明
正文段落……                         [展开全文]
```

### 5.3 键值信息

适用：岗位、部门、周期、当前节点、版本、来源等结构化字段。

- 列表：只选择最多 2 个有助于判断任务的字段，展示为短文本或标签。
- 抽屉：使用 2 列定义列表；移动端改为单列。
- 字段名称保持简短，不超过 8 个汉字；值过长时允许换行。
- 缺失值不统一显示为 `--`，应按语义显示「待分配」「待确认」「未填写」。

```text
考核周期  2026-07        当前节点  待一级领导评分
所属部门  内容中心       当前版本  V3
```

### 5.4 数值与指标

适用：绩效分数、完成数量、预算、目标值、招聘轮次、完成率。

- 列表：最多展示 3 个紧凑指标；优先展示结果、目标差距和异常值。
- 抽屉：每项使用「指标名 + 数值 + 单位 + 辅助说明」。
- 数值右对齐；单位弱化；正负变化必须带符号和语义，不能只靠颜色。
- 无数据时显示「待填报」而非 0，避免把缺失误读为真实零值。

```text
列表：目标 10项 · 已完成 8项 · 完成率 80%

抽屉：
[目标数量 10 项] [已完成 8 项] [完成率 80%]
```

### 5.5 进度

适用：项目阶段、任务完成率、材料准备进度。

- 列表：展示 `进度 80%` 或 `已完成 8/10`，只选一种主口径。
- 抽屉：使用进度条，并同时显示百分比、完成数和当前阶段。
- 进度为 0 时显示「尚未开始」；100% 显示「已完成」。
- 延期任务在进度旁增加异常标记，不把进度条整体改成大面积红色。

```text
当前阶段：剪辑一审       8/10
[████████░░] 80%          [延期风险]
```

### 5.6 清单

适用：材料清单、周报必填项、验收项、待整改事项。

- 列表：显示汇总 `已完成 3/5`，缺失项较少时可追加首个缺失项。
- 抽屉：展示只读清单，已完成项打勾，未完成项突出但不使用整行红底。
- 来源业务页：允许勾选、上传或补充，并保留操作记录。

```text
✓ 本周成果
✓ 风险与问题
○ 下周计划                         已完成 2/3
```

### 5.7 流程与步骤

适用：绩效审批、招聘面试、选题审核、项目节点。

- 列表：显示当前节点，不展示完整流程图。
- 抽屉：最多展示前一节点、当前节点、下一节点三段步骤条。
- 来源业务页：展示完整流程、处理人、时间和历史记录。

```text
目标确认（已完成） → 一级评分（当前） → 二级复评（下一步）
```

### 5.8 日期与时间

适用：任务下发时间、面试时间、计划周期、提交时间。

- 列表：统一展示任务下发时间，优先使用 `YYYY-MM-DD HH:mm`；缺失时显示“待记录”。
- 抽屉：任务概览仍展示完整任务下发时间；业务节点的起止时间放在内容区。
- 统一工作台不展示截止时间，也不生成今日到期、已逾期等时效标记。
- 日期范围格式统一为 `YYYY-MM-DD 至 YYYY-MM-DD`。

```text
任务下发时间：2026-07-20 09:00
```

### 5.9 人员与组织

适用：负责人、审核人、协作人、下发人。

- 列表：不展示人员姓名，底部仅展示来源业务单据。
- 抽屉概览：展示“处理角色”和“任务来源”，不展示负责人、下发人或协作人姓名。
- 具体人员信息仅保留在来源业务页面，用于实际处理和审计。

### 5.10 状态与标签

工作台任务状态仅分为三类：

| 状态 | 展示方式 |
|---|---|
| 待处理 | 蓝紫色浅底状态徽标 |
| 已退回 | 红色浅底状态徽标，并进入右侧退回提醒 |
| 已完成 | 绿色浅底状态徽标 |

- 不展示“进行中、待提交、待评分、待复核”等来源业务细分状态。
- 不展示高、中、低优先级或任何时效异常标签。
- 标签只写状态词，不写完整句子。

### 5.11 审批意见与评论

适用：领导评分意见、HR 复审意见、CEO 审批意见、面试反馈。

- 列表：展示审批结论与 1 行摘要，例如 `退回：缺少成本说明`。
- 抽屉：使用引用块展示结论、意见、提交人和时间。
- 多条意见只展示最新一条，提供 `查看全部 n 条`。
- 无意见时显示「尚未填写意见」，不展示空白框。

```text
[退回]
“缺少成本与场景可行性说明，请补充后重新提交。”
江晚 · 2026-07-20 14:30                 [查看全部 3 条]
```

### 5.12 风险、异常与退回原因

适用：延期原因、退回意见、申诉事项、数据异常。

- 列表：使用警示图标 + 原因分类 + 1 行具体说明。
- 抽屉：使用独立警示块，包含异常类型、具体原因、影响和要求动作。
- 红色用于已发生且必须处理的问题；琥珀色用于风险或临期提醒。
- 不使用纯红色大段背景；不能只显示「异常」而缺少具体说明。

```text
! 延期风险
原因：关键素材晚到
影响：剪辑一审预计延后 2 天
要求：更新节点计划并补充处理方案
```

### 5.13 关联对象与链接

适用：关联候选人、选题、项目、绩效单、周报周期。

- 列表：对象名称作为任务标题的一部分；只有选题和项目追加业务编号。
- 抽屉：使用关联对象卡，展示对象名、类型、编号和当前状态。
- 点击关联对象卡进入来源业务详情。
- 禁止暴露技术 ID。

### 5.14 文件附件

适用：证明材料、简历、方案文档、报表文件。

- 列表：只显示 `附件图标 + n 个附件`，不展开文件名。
- 抽屉：文件卡展示文件类型图标、名称、大小、上传人、上传时间。
- 默认展示前 3 个，更多时显示 `查看全部 n 个`。
- 支持预览的文件提供「预览」；不支持时提供「下载」或进入来源页。
- 文件不可用时显示「文件已失效」，并保留文件名和来源记录。

```text
[PDF] 目标证明材料.pdf
2.4 MB · 张小北 · 07-20 10:30              [预览]
```

### 5.15 图片与凭证

适用：招聘日报截图、现场照片、投放截图、证明图片。

- 列表：展示 `图片图标 + n 张图片`；原则上不直接铺图片，保持列表密度。
- 抽屉：使用 72–96px 缩略图宫格，最多显示 4 张，尾项可显示 `+n`。
- 点击缩略图打开大图预览，可左右切换。
- 加载失败显示占位图和「重新加载」，不能显示破图图标。
- 敏感图片按角色权限显示或打码。

### 5.16 表格

适用：目标明细、评分项、人员清单、项目任务明细。

- 列表：只显示 `n 条数据` 和最重要结论，例如 `12 项指标 · 2 项异常`。
- 抽屉：仅当列数不超过 4、行数不超过 5 时展示迷你表格。
- 超过限制时展示摘要和「查看完整表格」。
- 数字右对齐，文本左对齐；表头固定；异常单元格同时使用图标或文字。

```text
目标项        目标值    完成值    状态
内容产出      10        8         进行中
准时交付率    95%       91%       ! 未达标
```

### 5.17 分段内容

适用：周报三段式、方案的背景/目标/执行、项目风险/计划/结果。

- 列表：展示完整度，如 `3/3 部分已填写`；优先提示缺失分段。
- 抽屉：每段使用独立标题卡；空段显示「尚未填写」。
- 来源页：按原业务表单编辑，不合并成一个大文本框。

```text
[本周成果]  已填写 3 项
[风险与问题] 尚未填写
[下周计划]  已填写 2 项
```

### 5.18 版本与差异

适用：绩效目标版本、选题方案修改、审批退回后重提。

- 列表：显示当前版本与变更数，例如 `V3 · 变更 2 项`。
- 抽屉：使用前后对比，不使用一整段拼接文字。
- 删除使用删除线，新增使用新增标记；颜色之外必须有文字提示。
- 来源页：展示完整版本历史与操作人。

```text
目标权重
原值：20%
新值：25%  [已调整]
```

### 5.19 空缺、加载失败与无权限

| 状态 | 展示规则 |
|---|---|
| 必填内容缺失 | 显示 `待补充：内容名称`，并进入异常摘要优先级 |
| 可选内容为空 | 不渲染该内容区，不显示无意义占位 |
| 加载中 | 使用与目标内容结构一致的骨架屏 |
| 加载失败 | 显示失败原因摘要和重试入口 |
| 无权限 | 显示「无权限查看」，不暴露内容长度、文件名等侧信道信息 |
| 内容已失效 | 保留来源、时间和失效说明，提供返回业务页入口 |

### 5.20 敏感内容

适用：手机号、邮箱、身份证、薪资、申诉证据、内部评价。

- 工作台列表默认不展示敏感字段。
- 抽屉按角色权限脱敏，例如 `138****5621`。
- 无权限时不显示复制按钮，也不在 HTML 标题属性中放完整值。
- 完整值只在来源业务页按权限查看，并记录访问日志。

## 6. 业务场景应组合哪些内容格式

此表用于指导各业务把内容转成统一组件，不是为每个业务重新设计一套样式。

| 业务场景 | 列表主要摘要 | 抽屉内容组合 |
|---|---|---|
| 绩效目标下发/确认 | 标题 + 业务来源 + 状态 + 下发时间 | 键值信息 + 指标/表格摘要 + 版本差异 + 任务要求 |
| 绩效结果填报 | 完成率或待填报项数量 | 指标 + 清单 + 证明附件 + 任务要求 |
| 领导评分/复评 | 当前评分节点 + 异常项数量 | 指标 + 迷你评分表 + 审批意见 + 附件 |
| HR复审/CEO审批 | 审批节点 + 异常/例外数量 | 指标 + 异常提示 + 审批意见 + 关联绩效单 |
| 绩效反馈与面谈 | 面谈状态 + 计划时间 | 日期 + 人员 + 分段内容 + 改进清单 |
| 绩效申诉 | 申诉状态 + 核心争议摘要 | 风险/申诉说明 + 版本差异 + 证据附件 + 审批意见 |
| 候选人部门确认 | 候选人 + 岗位 + 当前节点 | 关联对象 + 键值信息 + 简历附件 + 任务要求 |
| 面试反馈 | 轮次 + 面试时间 + 待反馈状态 | 日期 + 人员 + 评分指标 + 审批意见 |
| 选题退回修改 | 退回原因摘要 | 长文本 + 退回意见 + 版本差异 + 关联对象 |
| 选题通过待立项 | 缺失配置项数量 | 清单 + 键值信息 + 长文本摘要 |
| 项目岗位任务 | 完成数/进度 + 当前阶段 | 进度 + 清单 + 附件 + 关联项目 |
| 项目延期更新 | 延期原因 + 影响天数 | 风险块 + 进度 + 日期 + 处理计划 |
| 周报未提交 | 缺失分段数量 | 分段内容 + 清单 + 日期 |
| 周报延迟补充 | 延迟原因 + 待补充项 | 风险提示 + 分段内容 + 附件 |

## 7. 当前任务卡片示例

任务卡片不使用“姓名 · 流程节点”结构，统一使用业务动作标题：

```text
[绩效]                                     2026-07-20 09:00
进行2026-07绩效评分
```

## 8. 内容选择决策规则

```text
任务是否只有一句行动说明？
├─ 是 → 使用短文本格式
└─ 否
   ├─ 是否为数值结果？ → 指标格式
   ├─ 是否表达完成程度？ → 进度或清单格式
   ├─ 是否为审核结论？ → 审批意见格式
   ├─ 是否为异常原因？ → 风险/退回格式
   ├─ 是否包含媒体？ → 文件或图片格式
   ├─ 是否为多条同构数据？ → 表格格式
   ├─ 是否为多段正文？ → 分段或长文本格式
   └─ 是否强调修改？ → 版本差异格式
```

一个任务可包含多种内容格式，但列表只选择一个主摘要；抽屉按以下顺序排列：

```text
任务对象与状态
→ 任务要求
→ 风险/审批意见
→ 关键指标或进度
→ 结构化字段
→ 内容正文/表格
→ 附件与图片
→ 来源与跳转
```

## 9. 数据结构建议

为避免每个业务模块自行拼接 HTML，建议任务详情使用统一的内容块协议：

```js
{
  id: "task-id",
  title: "业务对象 · 当前动作",
  summary: "一句话行动说明",
  module: "绩效",
  owner: "江晚",
  status: "待处理",
  issuedAt: "2026-07-20 09:00",
  contentBlocks: [
    { type: "metrics", items: [{ label: "目标项", value: 6, unit: "项" }] },
    { type: "progress", label: "确认进度", current: 4, total: 6 },
    { type: "comment", author: "江晚", result: "退回", text: "请补充说明" },
    { type: "files", items: [{ name: "证明材料.pdf", size: "2.4 MB" }] }
  ]
}
```

推荐支持的 `type`：

```text
text / long_text / key_value / metrics / progress / checklist /
steps / datetime / people / comment / risk / relation / files /
images / table / sections / diff / empty
```

每个内容块应声明：标题、内容、数据来源、更新时间、权限级别、列表摘要策略和详情展示策略。

## 10. 视觉与交互约束

- 默认任务行保持紧凑；普通任务约 88–96px，出现内容摘要时最多增至 112px。
- 列表内容摘要最多占 1 行；普通说明最多 2 行。
- 单行最多 3 个胶囊标签，更多信息使用纯文本计数或移入抽屉。
- 相同含义使用相同组件，不因业务模块不同而改变格式。
- 业务颜色只表达来源；状态颜色只表达状态；风险颜色只表达异常。
- 所有颜色含义必须同时有文字或图标，不能仅靠颜色区分。
- 缩略图、文件卡、表格和长文本只在抽屉中展开，避免破坏列表扫描效率。
- 鼠标悬停、键盘聚焦、加载、空、失败、无权限均需有明确状态。

## 11. 验收标准

### AC-01 内容格式识别

Given 来源任务包含文本、指标、进度、意见、附件或表格内容  
When 工作台生成任务展示  
Then 系统按内容类型选择对应展示组件  
And 不把所有内容统一拼接为无结构文本。

### AC-02 列表密度

Given 一个任务包含多种内容格式  
When 任务进入工作台列表  
Then 列表只展示一组最高优先级内容摘要  
And 任务说明不超过 2 行  
And 标签不超过 3 个。

### AC-03 三级展示边界

Given 用户查看同一任务  
When 分别处于列表、抽屉和来源业务页  
Then 列表展示摘要、抽屉展示关键内容、业务页展示完整内容和处理操作  
And 工作台不直接承担复杂编辑或审批。

### AC-04 状态语义分离

Given 任务同时具有业务类型、基础状态和异常状态  
When 页面展示任务  
Then 三类信息使用不同位置和样式  
And 不展示任务优先级  
And 用户无需仅依赖颜色即可理解状态。

### AC-05 媒体与附件

Given 任务包含文件或图片  
When 用户浏览列表与抽屉  
Then 列表只展示数量摘要  
And 抽屉提供文件卡或缩略图预览  
And 加载失败、失效和无权限状态可识别。

### AC-06 表格与长内容

Given 内容超过迷你表格或文本摘要限制  
When 用户打开任务抽屉  
Then 抽屉展示受限预览和查看完整内容入口  
And 不在抽屉中形成大范围横向滚动或无限长正文。

### AC-07 数据真实性

Given 工作台展示指标数量、附件数量、版本或进度  
When 页面加载  
Then 所有值均来自来源业务单据  
And 缺失值使用待填报或待补充语义  
And 不使用虚构的 0 值或示例值代替真实数据。

## 12. 已确认与待确认

### 已确认事实

- 用户需要按内容格式梳理展示方式，而非仅按业务任务类型分类。
- 当前截图主要使用「标题 + 行动说明 + 类型标签 + 负责人」的统一纯文本结构。
- 工作台任务需要支持不同内容形态的一致展示规则。

### 暂定假设

- 保留当前任务行基础骨架，在其上增加按内容类型变化的紧凑摘要区。
- 复杂内容在详情抽屉预览，在来源业务页完整展示和处理。
- 本次交付为产品与交互规范，不直接修改现有页面代码。

### 非阻塞待确认

- 是否在下一步把内容块协议实现为 React 通用组件。
- 是否需要为所有现有任务数据逐条配置 `contentBlocks`。
- 迷你表格、附件和图片预览的最终尺寸可在视觉稿阶段微调。
