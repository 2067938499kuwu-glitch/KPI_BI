# 统一工作台任务展示格式规范

> 本文记录统一工作台当前已经确认的任务展示口径。不同内容格式在详情抽屉与来源业务页中的展示方式，参见 [统一工作台任务内容格式与展示规则](./统一工作台任务内容格式与展示规则.md)。

## 1. 核心口径

- 统一工作台不存在“逾期”任务，不计算今日到期、已逾期或延期风险。
- 任务状态只有三种：`待处理`、`已退回`、`已完成`。
- 列表和详情中展示的时间均为“任务下发时间”，不是截止时间。
- 工作台负责汇总、查看和跳转；实际处理仍在来源业务页面完成。
- 任务数据来自绩效、招聘、项目、周报和 SSC，不在工作台另建一套状态。
- 工作台标题、摘要、卡片和详情概览不展示人员姓名；内部负责人字段仅用于权限过滤和任务路由。

## 2. 页面结构

统一工作台采用全宽任务看板样式：

1. 页面标题：任务工作台。
2. 汇总指标：我的待处理、已退回、当前已完成。
3. 全宽任务清单：按状态页签以双列卡片展示任务。
4. 任务详情抽屉：展示任务上下文，并提供进入来源业务页的入口。

不设置独立的“业务风险提醒”，避免与“退回”页签重复展示同一任务。

## 3. 汇总指标与状态页签

| 展示项 | 统计或过滤规则 |
|---|---|
| 我的待处理 | `status === "待处理"` |
| 已退回 | `status === "已退回"` |
| 当前已完成 | `status === "已完成"` |

列表页签与指标保持一致，仅包含：待处理、退回、已完成。

状态之间互斥：已退回任务只进入“退回”页签，不同时计入“待处理”；已完成任务只进入“已完成”页签。

## 4. 任务列表格式

### 4.1 单条任务的信息顺序

| 顺序 | 展示内容 | 规则 |
|---:|---|---|
| 1 | 业务标识 | 模块图标和业务来源；只有选题、项目追加业务编码 |
| 2 | 任务下发时间 | 优先显示来源业务提供的完整日期时间；缺失时显示“待记录” |
| 3 | 任务标题 | 一行主标题，直接说明任务对象和动作 |
| 4 | 任务摘要 | 最多两行，说明当前节点需要处理的事项 |
| 5 | 来源 | 展示来源业务单据，不展示负责人姓名 |
| 6 | 任务状态 | 只允许待处理、已退回、已完成 |
| 7 | 进入指示 | “查看详情”和右箭头，表示可打开任务详情抽屉 |

### 4.2 列表文字原型

```text
┌──────────────────────────────────────────────────────────┐
│ [图标] 业务来源 · 业务编码（仅选题/项目）      下发时间    │
│        任务标题                                          │
│        当前节点任务摘要                                  │
│        来源 · 业务单据       [任务状态]       查看详情  > │
└──────────────────────────────────────────────────────────┘
```

### 4.3 明确不展示

- 不展示今日到期、已逾期、剩余天数、截止时间或任务优先级。
- 只有选题、项目展示业务编码；绩效、招聘、周报和 SSC 不展示任何编码 ID。
- 不展示来源单据的长篇说明；任务摘要最多两行。
- 不在任务行中直接提供确认、提交、审批或完成操作。
- 不在单条任务中混合展示来源单据的完整字段。

## 5. 五类任务的展示映射

| 业务来源 | 标题示例 | 来源行 | 状态口径 | 下发时间来源 |
|---|---|---|---|---|
| 绩效 | `绩效目标2026-07待下发`、`确认2026-07绩效目标`、`进行2026-07绩效评分`、`进行2026-07绩效审核`、`进行2026-07目标异议处理` | `绩效` | 待处理；流程完成后为已完成；退回后为已退回 | 最近一次流程动作时间 |
| 招聘 | `确认候选人是否进入面试`、`确认候选人面试的时间以及面试官`、`提交候选人面试反馈`、`确认是否发放 Offer`、`确认是否已接受（同步到 SSC）` | `招聘` | 待处理；处理完成后为已完成；退回后为已退回 | 招聘申请记录更新时间 |
| 项目 | `《项目名称》 · 进行xx-xx剧集的上传/制作/剪辑/审核` | `项目 · PRJ-xxx` | 待处理；节点完成后为已完成 | 项目任务下发时间 |
| 周报 | `提交2026年W30周报`、`确认2026年W30周报补充项` | `周报` | 待处理；提交完成后为已完成；退回后为已退回 | 周报任务生成时间 |
| SSC | `进行人员花名册的添加` | `SSC` | 招聘进入待入职后为待处理；建档完成后为已完成 | 招聘待入职节点更新时间 |

来源业务若使用更细的内部流程状态，进入统一工作台时必须映射为上述三种状态之一，不直接展示“进行中、待提交、待评分、待复核”等细分状态。

## 6. 任务详情抽屉

详情抽屉固定展示：

1. 任务标题、业务来源和三态状态。
2. 处理角色，不展示具体人员姓名。
3. 任务来源。
4. 任务下发时间。
5. 任务要求及必要的来源业务摘要。
6. “进入业务页面”操作。

详情抽屉不展示截止时间、任务标记、逾期信息或独立的工作台处理按钮。

## 7. 已退回任务入口

- 顶部“已退回”指标展示当前角色数据范围内的退回任务数量。
- 点击“已退回”指标或“退回”页签，进入同一个退回任务视图。
- 页面不再设置独立的“业务风险提醒”区域，不重复展示退回任务。
- 当前没有已退回任务时，任务清单展示对应空状态。

## 8. 缺失与异常数据

| 场景 | 展示规则 |
|---|---|
| 下发时间缺失 | 显示“待记录”，不得替换为截止时间 |
| 状态缺失或不合法 | 在数据转换层映射为“待处理”，同时保留排查线索 |
| 处理角色缺失 | 按业务模块显示通用处理角色 |
| 来源单据失效 | 保留任务基本信息，并提示返回来源业务核查 |

## 9. 验收标准

1. 页面仅出现“我的待处理、已退回、当前已完成”三个汇总指标。
2. 列表仅出现“待处理、退回、已完成”三个页签。
3. 任一任务的状态只可能是待处理、已退回、已完成。
4. 列表及详情均使用任务下发时间，不出现截止时间。
5. 页面不出现今日到期、已逾期、逾期天数或时间风险标记。
6. 已退回任务只进入“退回”页签，不在其他区域重复展示。
7. 任务清单在桌面端采用双列卡片布局，并在窄屏下自动切换为单列。
8. 点击任务可查看详情并跳转到正确的来源业务页面。
9. 任务列表和详情概览不展示人员姓名。
